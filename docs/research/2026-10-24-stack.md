# excalillm — implementation stack and packaging

Research date: 2026-10-24. Scope: how the tool is assembled, installed, and kept alive. The product decisions (Remotion, Excalidraw fork, Jais/Audar, user's agent) are inputs, not re-opened here.

---

## Recommendation

**TypeScript/Node orchestrator with a Python sidecar behind a file+JSON seam.** One user-facing runtime (Node), one install command (npm), and Python reduced to a leaf process that does transcription and forced alignment. Jais runs as GGUF through a pinned, CI-built patched `llama.cpp` binary. Whisper large-v3-turbo via faster-whisper is the CPU floor and the automatic fallback. Remotion's pinned Chrome Headless Shell does both SVG export and video rendering, so there is one browser, one ffmpeg, one font stack. The Excalidraw fork is published to npm under a scope; users never build it.

Why not one language: a pure Node path forces whisper.cpp, which drops Arabic quality and has no real forced-alignment stage. A pure Python path still needs Node for Remotion and for building the React UI, so it does not remove a runtime — it only moves the awkward part (spawning a Node renderer and shipping a prebuilt UI) into Python.

### Process boundary

```
┌──────────────────────────── Node 22+ / TypeScript (the product) ───────────────────────────┐
│ excalillm CLI                                                                              │
│   init · setup · doctor · transcribe · plan · review · render                              │
│                                                                                            │
│  project dir (cwd)                          user cache (~/.cache/excalillm)               │
│   project.json                               models/jais-q4_k_m/…                          │
│   boards/scene_001.excalidraw                models/whisper-turbo-ct2/…                    │
│   audio/narration.m4a                        models/wav2vec2-ar/…                          │
│   .excalillm/transcript.json                 runtime/py312-<lockhash>/                      │
│   .excalillm/alignment.json                  bin/llama-jais-<platform>/                     │
│   .excalillm/plan.json                       chrome (package node_modules/.remotion)        │
│   out/animatic.mp4                                                                         │
│                                                                                            │
│  review server (127.0.0.1:0 + token) ──► system browser ──► @excalillm/excalidraw          │
│  SVG export + render ──► Remotion ──► pinned Chrome ──► bundled ffmpeg                     │
└──────────────▲──────────────────────────────────────────────▲──────────────────────────────┘
               │ spawn; JSON argv; JSONL progress on stderr    │ spawn; JSON argv
               │ files in / files out; exit code + signal      │
┌──────────────┴───────────────────────────┐   ┌──────────────┴──────────────────────────────┐
│ llama-jais (C++, pinned fork build)      │   │ Python 3.12 sidecar (uv venv)                │
│  text only, no word timings              │   │  asr: faster-whisper (fallback)              │
│  chunk 30 s + VAD in the wrapper         │   │  align: WhisperX + wav2vec2-ar               │
└──────────────────────────────────────────┘   └─────────────────────────────────────────────┘
               │
               └──► user's coding agent, spawned by Node (shell template or 4-file convention)
```

Seam rules that keep this maintainable:

- Python writes only its declared outputs (`transcript.json`, `alignment.json`). Node owns project state, caching, and all user-visible errors.
- Contract is versioned JSON Schema in `contracts/`; the sidecar prints `contractVersion` and exits non-zero with a machine-readable error code.
- No socket, no daemon, no Python web framework. One-shot processes, killed by process group on cancel.
- Model downloads happen in Node, before Python starts. Python runs offline (`HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`). This is what makes "local-first" testable.
- Re-running a stage is idempotent: output keyed by `sha256(audio + engine + model revision + settings)`.

## 1. Orchestrator language

| Option | How the other side is invoked | What the user installs | Fork maintenance | Verdict |
|---|---|---|---|---|
| Pure Node | whisper.cpp via a native binding or `whisper-cli` | Node only | Fork bundled into the app, built at release | Rejected: weaker Arabic, word timestamps are experimental token timings, no independent forced alignment |
| Python orchestrator | `subprocess` → `npx remotion render`; static UI shipped in the wheel | Python 3.12 + Node 22 + two package managers | Fork built into the static UI in CI; still a separate repo | Fallback only |
| **Polyglot, Node owner** | `spawn` Python sidecar; `spawn` llama binary; `spawn` agent | Node 22; npm package; uv/Python/models auto-installed | Published npm package; users never build it | **Recommended** |

The fork is the deciding weight. It is an upstream monorepo with its own build. If it lives in the main tree, every contributor pays for it and every `pnpm install` risks workspace coupling with Remotion's webpack config. Keep it in its own repo, publish `@excalillm/excalidraw` (MIT permits this), pin an exact version in the app. Budget one to two days per upstream minor; upstream's latest npm release is still 0.18.1, so churn is currently low.

Python version pin: **3.12**, not "whatever is on the machine". WhisperX 3.8.x supports 3.10–3.13; 3.12 has the broadest wheel coverage for torch/CTranslate2/onnxruntime.

## 2. STT and alignment packaging

### Options

| Option | Weight | Failure mode | Verdict |
|---|---|---|---|
| System Python + pip venv | 0 extra | Breaks on distro Python, PEP 668, missing headers | Reject |
| **uv-managed project venv** | uv ~15 MB; Python ~25 MB; deps ~250 MB (CPU torch path ~450 MB) | uv download blocked; repair path needed | **Recommended** |
| `uvx`/pipx per-invocation tool | small | Cold start per run, hard to pin a lockfile, no preload | Use only for the Python-first fallback |
| Docker image | 3–5 GB image; GPU passthrough, bind mounts, browser/audio pain | Desktop file access and GPU are the whole product | CI/render farm only |
| Direct binaries | ~15 MB per platform | We must build and sign them | **Recommended for Jais** |
| whisper.cpp Node-only | ~3 GB model | No phoneme alignment; Arabic ceiling | Emergency fallback |

### Models: what is actually downloaded

| Role | Model | Download | Runtime | GPU floor | License | Notes |
|---|---|---|---|---|---|---|
| Arabic ASR (quality) | Jais-ASR GGUF Q4_K_M + mmproj | **3.71 GB** | patched llama.cpp fork | **5.03 GiB peak** (4-bit) | Apache-2.0 | Requires MBZUAI-IFM fork + `llama.cpp-jais-asr.patch`; fork had **zero GitHub releases** on 2026-10-24, so we build per-OS binaries in CI |
| Arabic ASR (easy install) | Audar-ASR-V1-Turbo Q4_K_M + BF16 mmproj | 1.28 + 0.64 GB | recent upstream llama.cpp (Qwen3-ASR) | ~2–3 GB | **AudarAI Community License** (not OSI) | Easiest runtime, worst licensing for an open-source default; opt-in only |
| Arabic ASR (CPU floor) | faster-whisper large-v3-turbo CT2 | 0.78 GB int8 / 1.62 GB fp16 | CTranslate2, CPU or GPU | ~1.5 GB | MIT | 809M params; ~2–4× realtime on 8 CPU cores |
| Arabic ASR (fallback quality) | faster-whisper large-v3 CT2 | 3.09 GB | CTranslate2 | ~3 GB | MIT | Slower; only if turbo is insufficient |
| Forced alignment | `jonatasgrosman/wav2vec2-large-xlsr-53-arabic` via WhisperX | 1.26 GB | torch | ~1.3 GB | Apache-2.0 | Arabic is in WhisperX's default align map (`"ar"`) |
| Optional aligner | ctc-forced-aligner (MMS ONNX) | ~1.2 GB | onnxruntime, no torch | ~1.5 GB | BSD code; **default MMS model CC-BY-NC** | Saves torch, but the default model is non-commercial; avoid unless relicensed |

Source sizes are from the model cards/file listings; see the verification table.

**The floor.** Jais is not a 12 GB proposition at 4-bit: the published Q4_K_M config peaks at 5.03 GiB. An 8 GB GPU is comfortable, 6 GB is tight, and the alignment model should load *after* Jais exits so peaks do not stack. Machines without a GPU should not run Jais by default: 4-bit 4B-class decoding on 8 cores is plausibly 0.3–1× realtime (inferred, unmeasured), so a 25-minute talk could take 25–80 minutes before alignment. Whisper turbo on the same machine is roughly 6–12 minutes. Therefore:

```
stt.engine = auto
  GPU with >= 8 GB VRAM  -> jais (GGUF, patched binary)
  otherwise              -> whisper-turbo (faster-whisper int8)
```

Apple Silicon: the fork is llama.cpp, so a Metal build should work with unified memory, but this is unverified and not a v1 promise. Default Apple Silicon to whisper-turbo, offer Jais as opt-in.

### Weights location

- `~/.cache/excalillm/models/<model-id>/<revision>/` (XDG on Linux, `~/Library/Caches` on macOS, `%LOCALAPPDATA%` on Windows), overridable with `EXCALILLM_CACHE`.
- A `manifest.json` per model: URL, size, sha256, license, source revision. Node downloads with resume + lock file + atomic rename. Doctor validates size and hash.
- Nothing is downloaded at transcription time. A `--offline` install is a first-class path: copy the cache directory.
- Do not put weights in the project directory. A 25-minute project should stay a few MB of boards and audio; derived artifacts go to `.excalillm/`.

### Python dependency detail that saves 2 GB

WhisperX's lock resolves torch 2.8 from PyTorch's CUDA index on Linux x86_64. A naive install pulls ~2.5 GB of CUDA wheels. The setup command must install CPU torch first from `https://download.pytorch.org/whl/cpu` (torch 2.8.0+cpu, ~200 MB) and then `uv sync --frozen`; the requirement is already satisfied, so the CUDA wheels are never fetched. On macOS arm64 the torch wheel is 73.6 MB. On macOS **x86_64 there is no torch 2.8 wheel at all**, so Intel Macs cannot run the WhisperX aligner; the only alternative aligner there is the CC-BY-NC ONNX model, so treat them as unsupported for v1.

`stable-ts` is not an option: the repo was archived on 2026-05-30 and development is paused. WhisperX is the maintained aligner.

## 3. Distribution

| Channel | Verdict | Why |
|---|---|---|
| **npm global** (`npm i -g excalillm`) | **Primary** | Node is already required by Remotion; one package, stable path for Chrome's `node_modules/.remotion`; `npx` for trials but not the supported install |
| `npx excalillm` | Trial only | npm may evict the cache dir, forcing a Chrome re-download; models still live in the user cache |
| Homebrew / winget | Later, thin wrapper | Formula depends on `node` and runs the npm install; no separate code path |
| pipx / `uv tool` | Fallback stack only | Would make Python the entry point and still require Node |
| Signed binary per OS | No | Node is needed anyway; bundling it plus native deps adds ~80 MB and a signing pipeline for little gain |
| Docker | CI/render farm only | GPU, bind mounts, browser, and fonts are exactly the hard parts on a desktop |
| Clone + `make` | Contributors only | Acceptable for the repo, not for the target user |

What Remotion already supplies, and therefore what the installer does **not** need:

- Chrome Headless Shell (~150 MB) is downloaded into `node_modules/.remotion/chrome-headless-shell/<platform>/` and version-pinned (`157.0.8080.0` for 4.0.538). Use `ensureBrowser()`.
- ffmpeg and ffprobe are shipped in the per-platform `@remotion/compositor-*` package (27 MB unpacked, ffmpeg 7.1 line). `npx remotion ffmpeg` exists. **Do not require system ffmpeg**; only warn if the user asks for a feature that needs the full build.
- Linux still needs shared libraries (`libnss3`, `libgbm`, `libasound2`, etc.). The installer cannot bundle glibc; doctor must check with `ldd` and print the distro-specific `apt/dnf` line.

The Excalidraw fork: publish `@excalillm/excalidraw@0.18.1-ar.N` plus its CSS, consume it as an exact dependency in `packages/studio` and `packages/render`. Users never clone or build upstream. The review UI is a static Vite build served by the CLI on `127.0.0.1` with an ephemeral port and a per-session token; no Electron, no signing, no 100 MB shell. Fonts must be self-hosted and `window.EXCALIDRAW_ASSET_PATH` pointed at the local asset root; upstream otherwise fetches fonts from a CDN, which breaks offline use.

The agent stays external: `init` writes `agent.mode` (`files` by default, `shell` opt-in), a command, and a timeouts block. Default to the four-file convention because it avoids shell quoting on Windows entirely; the shell template is for agents that cannot read files.

Remotion licensing is a distribution fact, not a code fact: free for individuals and companies up to 3 people, company license above that. Put it in the README and in `excalillm doctor` output once, not in a modal.

## 4. `doctor`

Run every check, do not stop at the first failure, print a summary table, exit 1 if any fail. Order is cheapest/foundational first, network-dependent and slow last.

| # | Check | Pass condition | On failure, tell the user |
|---|---|---|---|
| 1 | Platform / arch / WSL | linux-x64, linux-arm64, darwin-arm64, win32-x64 | "Unsupported platform. Supported: …" |
| 2 | Disk | ≥ 8 GB free in cache + project (15 GB recommended) | "Free space or set `EXCALILLM_CACHE` to another volume" |
| 3 | Node | ≥ 22.12 (tested on 22/24/26) | `nvm install 22` / `winget install OpenJS.NodeJS.LTS` |
| 4 | uv | managed uv present (or on PATH) | `excalillm setup --bootstrap` (downloads uv into the cache) |
| 5 | Python | 3.12.x resolves via uv | `uv python install 3.12` |
| 6 | Python env | `import faster_whisper, whisperx` succeeds; contract version matches | `excalillm setup --repair-python` |
| 7 | ffmpeg/ffprobe | bundled Remotion binaries run | `excalillm setup --repair-render`; on Linux print the shared-lib apt line |
| 8 | Chrome | version file matches the pinned Remotion version; `ldd` clean | `excalillm setup --repair-browser` |
| 9 | Arabic fonts | Noto Naskh Arabic + Amiri load in the pinned Chrome; shaping smoke test renders non-tofu | reinstall the npm package / restore `assets/fonts` |
| 10 | Models | manifest, size, sha256 for the selected engine + aligner | `excalillm models add jais` / `… align`; show GB needed |
| 11 | GPU / engine | not a failure; report VRAM and which engine `auto` selected, plus an ETA band | `excalillm config set stt.engine whisper` to force CPU |
| 12 | Agent command | binary resolves; fixture prompt returns within timeout; output parses and validates against `plan.schema.json` | print config path, exit code, last 20 lines of stderr, and the first JSON Pointer that failed (`/scenes/2/cues/0/elementId`) |
| 13 | Smoke (`--smoke`) | 10 s sample: transcribe + align under 3× the clip duration | keep the temp dir and print its path |

## 5. Repo layout

Plain **pnpm workspaces**. No Turborepo, no Nx, no Changesets in v1. Five TypeScript packages is below the threshold where a task graph pays for itself; `pnpm -r --if-present build` and CI caching are enough.

```
excalillm/
├── package.json                 # private; "packageManager": "pnpm@10.x"
├── pnpm-workspace.yaml          # packages/*
├── tsconfig.base.json
├── biome.json                   # or eslint+prettier; one formatter, no debate
├── contracts/
│   ├── project.schema.json
│   ├── stt.schema.json
│   └── plan.schema.json
├── packages/
│   ├── cli/                     # bin: excalillm; init/setup/doctor/transcribe/plan/render
│   │   ├── src/
│   │   └── py/                  # uv project, shipped inside the cli npm tarball
│   │       ├── pyproject.toml
│   │       ├── uv.lock
│   │       └── src/excalillm_stt/{__main__,asr,align,protocol}.py
│   ├── core/                    # project state, schema validators, cue compiler, cache/manifest
│   ├── render/                  # Remotion Root + composition; export-to-SVG via pinned Chrome
│   ├── studio/                  # Vite + React review app; @excalillm/excalidraw
│   └── assets/                  # fonts (Noto Naskh, Amiri), icon pack, licenses
├── examples/demo/               # 20 s project checked in; used by doctor --smoke
├── docs/                        # ADRs, agent template, troubleshooting
└── .github/workflows/           # ci.yml, release-npm.yml, build-llama-jais.yml
```

Why this is the minimum:

- `cli` and `core` could be merged, but `render` and `studio` both need the schemas; a third consumer justifies the split.
- `assets` is a package so both the UI and the render bundle resolve fonts and icons the same way, and npm `files` includes them once.
- The Python project lives inside `packages/cli/py/` (not at the repo root) so npm's `files` can ship it without reaching outside the package. It is not a pnpm workspace member; pnpm and uv do not share a lockfile. They meet at `contracts/` and at `spawn`.
- The fork is not in this tree. It is `github.com/<org>/excalidraw`, branch `excalillm/0.18.1`, CI publishes `@excalillm/excalidraw`. The main repo pins `0.18.1-ar.<n>` exactly.
- SVG export uses `openBrowser()` from `@remotion/renderer` (returns a `puppeteer.Browser`), loads a tiny bundled page that imports the fork's `exportToSvg`, and writes the markup next to the board. Then Remotion renders with the same browser instance. No Playwright, no resvg, no second Chromium, and the exported SVG uses the exact Chrome/font pair that will rasterize it.

Release wiring: one `npm publish` per package. `@excalillm/cli` ships `py/` in its tarball (`files: ["dist", "py"]`) and `setup` materializes it with `uv sync --frozen` into the cache. No PyPI release cadence, and CLI and sidecar are always the same version. The fork has its own tag and publish; the app's dependency bump is a one-line PR.

## 6. Install and first-run cost

| Stage | Download | Disk | Time @50 Mbps | When |
|---|---|---|---|---|
| `npm i -g excalillm` (CLI + Remotion + React + fork) | ~150 MB | ~500 MB | ~30 s | install |
| Chrome Headless Shell + compositor | ~180 MB | ~230 MB | ~30 s | `setup` (or first render) |
| uv + CPython 3.12 + venv (CPU torch, WhisperX, faster-whisper) | ~450 MB | ~800 MB | ~1.5 min | `setup` |
| Whisper turbo int8 + wav2vec2-ar | 0.78 + 1.26 GB | 2.1 GB | ~5.5 min | `setup` |
| Fonts + icons | ~10 MB | ~15 MB | ~2 s | install |
| **Default total** | **~2.8 GB** | **~3.5 GB** | **~8 min** | |
| Jais GGUF Q4_K_M + mmproj | +3.71 GB | +3.8 GB | +10 min | first Jais transcription, or `models add jais` |
| Audar Turbo (optional) | +1.92 GB | +2.0 GB | +5 min | opt-in only |
| **With Jais** | **~6.5 GB** | **~7.4 GB** | **~18 min** | |

At 30 Mbps the default is ~13 min and with Jais ~29 min; at 100 Mbps roughly 4 and 9 min. Defer everything that is not needed for the selected engine: browser until the first export/render, Jais until a GPU machine asks for it, Audar until the user accepts the license, icons until the review/plan stage. A 25-minute 1080p30 render still costs ~28 minutes on 8 cores, and output is ~0.5–1.5 GB.

## 7. Windows

**Native Windows is a supported answer; WSL is not required.** Each piece has a native path:

- Node and Remotion: win32-x64 Chrome Headless Shell and `@remotion/compositor-win32-x64-msvc` are first-class.
- Python: uv + CPython 3.12 + ctranslate2/onnxruntime win_amd64 wheels exist; torch 2.8 win_amd64 exists.
- Jais: llama.cpp builds under MSVC; our CI produces `llama-jais-win32-x64.zip`.
- Review UI: browser; no native window.
- Fonts: Chromium bundles its own shaping; no system font install needed.

Caveats to encode in doctor:

- Remotion's shared-memory frame capture is macOS-arm64/Linux only. Windows falls back to JPEG/PNG capture, so expect a slower render at 1080p (inferred, likely 20–40%).
- Windows Smart App Control has blocked Remotion's bundled `ffprobe.exe` in the wild. Doctor should treat that as a known failure with a specific message.
- Long paths and spaces: keep the project under the user profile, check `MAX_PATH` headroom, and use argv arrays everywhere (the four-file agent mode avoids shell quoting entirely).
- Agent shell templates: default to `files`; if `shell`, store separate `cmd`/`pwsh` templates, not a POSIX string.
- Windows on ARM is experimental: ctranslate2/onnxruntime wheel coverage is the blocker.

WSL2 works (Linux binaries, localhost forwarding for the review UI), but it is a fallback for users who already live there. Warn about `/mnt/c` I/O and GPU setup cost. macOS Intel is the one real platform gap: torch 2.8 has no x86_64 macOS wheel, so the WhisperX aligner cannot install. The only working aligner there is the ONNX path whose default model is CC-BY-NC, so mark Intel Macs unsupported for v1 rather than shipping a non-commercial default to them.

## Fallback stack

**Python-first, Node as a render subprocess.** `uv tool install excalillm`, Python owns project state, STT, alignment, schema validation, and calls a pinned Remotion install in the cache for render. The review UI is a prebuilt static bundle shipped in the wheel; the Excalidraw fork is built into that bundle at release time.

```
uv tool install excalillm
excalillm setup          # checks Node 22, installs Remotion into the cache
excalillm doctor
```

Choose this only if the sidecar grows into the product (diarization, multi-speaker, audio preprocessing) or the maintainer is Python-native. It does not remove Node, adds a second release pipeline, and makes the UI harder to iterate on. It is a worse default for the same reason the recommended stack exists: the UI and render are the Node-shaped parts, and the user should type one command.
